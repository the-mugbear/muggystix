# Frontend

**`documentation/UI_STYLE_GUIDE.md` (the § numbers) owns every UI rule**; this is the short form plus code conventions. The barrel, project-role controls, TanStack-only server state, URL list state and desktop-only are in the root `AGENTS.md`.

## Lint, build, tests

- **Lint is the gate's** (`eslint.config.mjs`, `--max-warnings 0`): rules-of-hooks, exhaustive-deps, `@tanstack/query/exhaustive-deps`, the barrel (`@typescript-eslint/no-restricted-imports` on `**/services/api/*`, type-only allowed; a submodule loads the real client, which fails in jsdom), selectors `DOWNLOAD_NAME`, `BARE_MOMENT`, `BARE_DAY_OR_TIME` (with options allowed), `OBJECT_URL`, and `eslint-rules/`: `bluestick/api-in-query-only`, `bluestick/query-fn-signal`, `bluestick/state-from-address` (`tests/lint/`). A convention that can be a lint rule goes there. Build: `noUnusedLocals` / `noUnusedParameters`.
- `setupTests.ts` gives each render a fresh client and runs the notify manager inside `act` (`tests/lib/query.test.tsx`): never wrap your own or mock `@tanstack/react-query`, except to test what is REMEMBERED between mounts (one `createQueryClient()` as each render's `wrapper`; `tests/pages/Scans.commandDetail.test.tsx`; `documentation/TESTING_FRAMEWORK_DOCUMENTATION.md`). Still `await` what the reader sees (`findBy…`, `waitFor`); fake timers: `advanceTimersByTimeAsync`.
- A hook owning a state machine takes its API as injectable deps, tested with `renderHook` (`hooks/useUploadReview.ts`).

Add-member starts on `DEFAULT_MEMBER_ROLE` (Viewer) (`tests/utils/projectMembers.test.ts`; hazard — removable: a source-scan test that every member-write caller imports the decisions).
- **Export dialogs: `components/GeneratedTextDialog`** (`ScopeExport` — the DECLARED scope —, `ToolReadyOutput`): labels and names the file (`heading` / `filename`) by the mutation's `variables`, never the picker; a caller gives `generateFn`, formats, words. An empty answer is said (`empty`, or why) (`tests/components/ExportDialogs.reopen.test.tsx`, `ExportDialogs.format.test.tsx`; hazard — removable: a source-scan test refusing a second export dialog).
- **Closing a finding's "why?": `components/findings/StatusReasonDialog`**, opened a tick after the Select's `onValueChange` (Findings single and bulk, finding page, inspector), sent with the status — never a navigation dropping the choice (hazard — removable: a source-scan test that nothing else asks for a reason).
- **Dimmed and inert: `utils/uiStyles.inertWhen(on)`** (`inert`; `pointer-events-none` leaves rows keyboard-reachable): Hosts, Findings (a left filter's rows while the next loads), Scope editor (hazard — removable: a lint selector refusing a hand-set `inert` / `pointer-events-none` toggle).
- **A pasted image: `utils/clipboardImages.imagesFromClipboard` only** (it may be only in `files` or only in `items`); the images panel takes only a paste inside it (or nothing focused) no field took (`defaultPrevented`) (`tests/utils/clipboardImages.test.ts`; hazard — removable: a lint selector refusing `clipboardData` elsewhere).
- **Copy: `utils/clipboard.copyToClipboard`; the icon `ui/code-block.CopyButton`** (`size="compact"` on a row) (hazard — removable: a lint selector refusing `navigator.clipboard` elsewhere).
- **A selection is never fanned out by a bare `Promise.all`**: `utils/runLimited` (bounded `allSettled`) (hazard — removable: a lint selector on `Promise.all(… .map(…))` in pages / components).
- **An endpoint on a NAME is chosen with `components/names/HostNameSelect`** (`useHostNameChoice` owns the read — `['getHostNames', projectId, hostId]`, the key `HostNamesCard` shares — and the choice; the component draws it, nothing for a host with no current name): the host page's Add finding (`components/findings/AddFindingForm`, also the Names sheet's dialog) sends `name_id`, the Add test panel (`hostTestsController.AddTestPanel`, exported for the Names sheet) sends `target_fqdn`; both offer exactly the names the server accepts (`dns_name_service.name_observed_at_host`) (hazard — removable: a source-scan test refusing a second reader of `getHostNames` outside the hook and `HostNamesCard`).
- Client-free helpers live in `utils/` (`duplicateUpload.ts`, `hostSelection.ts`, `hostTests.ts`, `evidenceFreshness.ts`, `findingStatus.ts`, `runLimited.ts`, `projectMembers.ts`, `csv.ts`, `routeId.ts` — the ONE reading of a route's record id —, `plural.ts` — the one count-and-noun helper).
- A Hosts row's matched-term and `exposure` chips are the server's (`inventory-reads.md`); the page only words them. A Hosts link keeps any review state (`watching` too) for the server's 422.

## Server state (§48, `src/lib/query.ts`)

- API calls only in a `queryFn` / `mutationFn` (`bluestick/api-in-query-only`; a barrel export making no request joins `NOT_REQUESTS`). Key = function name, then arguments.
- **The project is an argument**: a project-scoped API function takes `projectId` FIRST (`projectPath(projectId)`), from `useProjectId()` (`NO_PROJECT` = 0) or a row's `project_id`; key `['listThings', projectId, filters]`; no hidden partition, no `GLOBAL` marker (`['getProjects']`) (TypeScript + `@tanstack/query/exhaustive-deps`). `getCurrentProjectId` / `setCurrentProjectId` are the remembered SELECTION only (ProjectContext, `utils/scopedStorage`) (hazard — removable: an import restriction on them outside those and `services/api`).
- The cache clears when the signed-in user changes (AuthContext). Nothing is copied from a query into state; a form keeps the reader's edits.
- **A write refreshes what it changed**: `setQueryData(['apiFn', projectId, …])` / `invalidateReads(queryClient, 'apiFn', …)` (by name) — never a `reload` prop, `refreshKey` or window event. Hand-kept lists: `OPERATIONS_READS`, `REMEDIATION_READS`, `INGESTION_JOB_READS`, `PROPOSAL_DECISION_READS`, `AGENT_SESSION_READS`, `MEMBERSHIP_READS` (`hooks/useProjectMembers`), Names', Scans' two; a new read of an area joins its list (hazard — removable: a per-list test that every barrel read of the area is named).
- **A failed read is logged once**: `logFailedRead` on the app client's cache (name, status, message; never arguments or a cancellation). No `try`-to-log in a `queryFn`; tests' clients do not log (no `logFailures`) (hazard — removable: a lint selector refusing `console` / `logger` in a `queryFn`).
- **Defaults are deliberate** (no retry, `retryOnMount: false`, no focus refetch, `gcTime: 0`, `networkMode: 'always'`, `staleTime: 0` — a later reader re-asks unless it sets `staleTime`, as `AgentSessionsLine`); never override for a page's problem. An own lifecycle gets a comment and a test: `rememberFor(ms)` (members, installation settings), `retryOnMount: true` (the scan's argument analysis).
- **A remembered read says what a failure does**: `useRemediationPolicy` (`rememberFor(Infinity)`) returns `error` + `retry` and re-asks each minute while failing — never "off" (`tests/hooks/useRemediationPolicy.test.tsx`).
- **Polling: `...pollEvery(ms | (query) => ms | null)`**, never a bare `setInterval` (`hooks/useNow` is a clock). A poll stops in a hidden tab; only one that must keep FOLLOWING passes `{ inBackground: true }` (presentation mode's heartbeat, `hooks/usePresentationSync`). "Probably out of date": `useFailureStreak(query) >= n`, never a counter in a `queryFn`.
- **A GET takes `signal?: AbortSignal`** (last, or in options: `getHost`, `listAgentSessions`); a `queryFn` passes its own, a `mutationFn` none; click-only downloads are the `noSignal` list (`bluestick/query-fn-signal`).
- A secret-carrying mutation spreads `SECRET_MUTATION`, is `reset()` once used (`tests/helpers/heldByMutations`).
- A cached finding merges by `revision` (`findingCache.putFindingAnswer`, `keepNewerFinding`; `triage-tests-proposals.md`).

## Lists and the address

- **"Show more" is `hooks/useListQuery`** (§39 owns its parts: `keepPrevious` + `isPrevious`, `lastResponse`, `loadMoreError` — `loadMore().catch(() => undefined)`, no mutation around it —, `dedupeBy`, `failure`, `hasMore`, `responses`, `retrying`). A reload re-reads every loaded page (`usePagedList` where one page at a time will do). Never `useInfiniteQuery` in a page, a generation counter / `cancelled` flag / `AbortController`, or a ref of the last answer (`tests/hooks/useListQuery.test.ts`; hazard — removable: an import restriction on `useInfiniteQuery` outside the hook).
- A NEW filter's failure: `keepPrevious: true` keeps rows under the error, `'loading'` only while loading (Scans, session history). "Load older sessions": `offset`, 200 a read, within the route's `limit`.
- While another key loads: `useLastSettled(query.data)` (forgotten on unmount and by `resetKey`; project pages `{ resetKey: projectId }`, list hooks `within: projectId`). **A job: `hooks/useJobPoll` / `useJobPolls`** (first reading = the POST's answer; not asked once finished; a failed poll: "Status may be stale — …").
- **A paged list's page is in the URL**: `usePagedList('apiFn', fetchPage, deps, { pageSize, page: useUrlPage() })` (`?page=`, omitted for 1, replacing the entry); new deps → 1; tab / filter links carry no `page`. `keepAddressPage` (Findings, audit log, Hosts): a link naming filters AND a page opens it; a filter control returns to 1 by leaving `page` out of its ONE write (`AuditLog.address.test.tsx`, `Hosts.test.tsx`). `enabled: false` parks it; past-the-end steps back, only here. Key `[apiFn, ...deps, { page, pageSize }]`; a returned row via `list.mapRows`. ONE page reading: `pageFromParams` (`hooks/useUrlPage`, digits; `tests/hooks/usePagedList.url.test.tsx`).
- **Paged footer: `components/operations/QueueParts.PagedFooter`** (`busy` while loading), in-memory paging too; Findings and Hosts use `ui/data-table`'s `DataTablePagination` (hazard — removable: a source-scan test refusing hand-built page buttons).
- **A committed filter is read from the address and changed by writing it, once per action** (two `setSearchParams(fn)` in a tick lose one); only a draft is state (`hooks/useUrlSearchDraft`, no hand `setTimeout`). `bluestick/state-from-address` refuses `useState(…Params.get(…))`; its two disables, `useUrlSearchDraft` and Oversight's dates, re-seed on address change. A page's `*.address.test.tsx` uses the real router: same-page link, Back.
- **Hosts state is the URL** (§39; `sessionStorage` only seeds a bare `/hosts`; `navigate(buildHostsUrl(...))`): `usePagedList` + `keepAddressPage`, `enabled`, its own `{ page, setPage, search }`; `commit` is the one address writer. Filter options: ONE query `['getHostFilterData', projectId, conditions]`, after the list answers, then only while "+ Add filter" is open.

## Records, dialogs, projects

- Detail pages rely on `<ErrorBoundary key={location.pathname}>` and `Layout`'s per-project key; a `CROSS_PROJECT_ROUTES` page (`ProjectContext`) keeps its query on a switch.
- **Opening another project's page: `hooks/useOpenInProject`** (`openInProject(projectId, to)`: select, then navigate; false for a project not in the reader's list → `cannotOpenProject(name)`). A notification on an `isCrossProjectPath` or with no project opens without a switch; an unopenable one says so, stays unread (hazard — removable: a source-scan test refusing `setCurrentProjectId` + `navigate` outside the hook).
- **A record-scoped panel is keyed by its record** (`<Body key={hostId}/>`: `HostInspector`, `HostFindingsCard`, `HostTestsSection`) for LOCAL state; its data by query key (`['getHost', projectId, hostId, { includeInfo }]` — what the reader asked to see is in it; writers invalidate `['getHost', projectId, hostId]`). A write puts the server's ANSWER on it (`putHost`: cancel in-flight reads, `setQueriesData`, invalidate — `invalidateQueries` alone joins a read in flight; `tests/components/HostInspector.reviewDialog.test.tsx`); no "done" map, no "still this host?" check. `RemediationTimeline`'s sheet stays mounted, body keyed by host.
- Inspector: `HostInspectorBody` (reads; early returns last) → `HostInspectorView` (none); writers in `host-inspector/` (`ScannerObservationsSection`, `HostDiscussionSection`, `HostReviewControls`) — no hook below an early return.
- **A dialog that opens clean is keyed by its opening** (`<Body key={useOpeningKey(open)}/>`, or the record's id), never an effect on `open`; what it keeps across openings lives outside the body (`GeneratedTextDialog`'s format; `AiDraftReportDialog`'s audience, instructions) (`tests/components/OpeningDialogs.reopen.test.tsx`).
- **A composer with screenshots: `hooks/usePendingAttachments` + `host-inspector/NoteComposer`** (a failed upload stays bound to its saved note with Retry / Remove, reconciled by id) (hazard — removable: a source-scan test that nothing else uploads note attachments).
- Port tables: 200 rows in port order + "Show N more" (`PortDetailsCard`, `PORT_ROWS_STEP`; `tests/components/PortDetailsCard.rows.test.tsx`). `SafeMarkdown`'s closers: one linear pass (`utils/markdownScan.ts`). Measured and left alone: `linkDestination`, `reportImages.codeSpans` mildly quadratic; revisit if a text stalls.
- An unknown count is "—" / "…", never 0.

- **A report file's button: `components/DownloadButton`** (§45; keyed by what it downloads); `InventoryDownloadDialog` keeps its own busy state (`tests/components/DownloadButton.test.tsx`). Hand reordering: `components/reports/ReorderableRows` + `utils/reorder.moveItem` (a key per row).

## Presentation mode (§49)

- The stage draws the SERVER's slides (`components/presentation/Stage.tsx`) at the server's `stage` sizes (CSS variables); never paginate or measure in the browser except the fit fallback, which never changes the slide list. The stage alone imports the `@fontsource` fonts.
- The client state machine is `utils/presentationSync.ts` (plain TS, injected transport; three-client tests in `tests/utils/presentationSync.test.ts`): one answer rule (lower revision ignored, equal refreshes presence, higher accepted), a serialized + coalesced move queue, "awaiting reconciliation" after an unknown outcome. A tab id is made in memory per page load, never in `sessionStorage` (a duplicated tab copies it).
- A Display acknowledges a render only for the revision it still shows, after fonts and images (`Stage`'s `onRendered` token).
- 5.426.1 (review 2026-10-24): an accepted ENDED state re-reads the report's live presentation (`getLivePresentation`), so the heartbeat stops, Start is offered and a Display follows the next Start — never a tab polling an ended row; a Browse tab heartbeats every `BROWSE_POLL_MS` (5 s), following tabs every second; presenter-remote keys (Page Down / Up, arrows; not Space) step like `j` / `k`; the slide list keeps its current row in view (`keepCurrentInView`, the list alone). 5.426.2: a Display's render acknowledgment belongs to ONE presentation (`renderedAck(presentationId)`; dropped when another is accepted) — the sync outlives a presentation, and the server 422s a revision the new one has not reached; an ended presentation is never "reconnecting". A page test of a presentation change renders the first one before it ends (`tests/pages/Presentation.test.tsx`). 5.427.0 (reviews 2026-10-24b/c): `?start=1` is spent by the first live read either way (kept, it started a new presentation when the joined one ended); a failed live / agendas / filter read is said, never shown as an answer (`live-read-failed`, `agendas-failed`, `filter-failed`); only the LATEST filter choice lands (`filterAsked`); a Browse tab's stale threshold is `BROWSE_POLL_MS + STALE_AFTER_MS`; `SlideList` is `React.memo` with an `onPick` reading position and agenda through refs (both are new objects on every answer); `HostFilterControl` is keyed by a text filter's words.
- 5.425.0: the agenda state is part of `Target` (`samePosition` compares it); a move's own success settles the target it sent. Agenda navigation is `utils/presentationAgenda.ts` over the server's `slide.anchors` — never a membership rule of its own (`tests/utils/presentationAgenda.test.ts`). The spotlight is kept by highest `seq` apart from the revision rule; `spotlightShown` rings it on a Controller's accepted / a Display's RENDERED revision. Previews (`PresenterView`) are the stage component in a small frame; the slide-list read is ONE (`components/presentation/slidesQuery.ts`).
- Browser suites: `e2e/` (Playwright, `npm run e2e`, a gate step): `presentation-overflow.spec.ts` draws `e2e/fixtures/presentation-worst-case.json` — the slide builder's own output, pinned by `backend/tests/test_presentation_e2e_fixture.py` (regenerate after an estimator change) — and `presentation-multi-user.spec.ts` runs three contexts over `e2e/fakeBackend.ts`, which mirrors the server's rules (keep them in step with `presentation_service`). The width table `backend/app/data/presentation_metrics.json` comes from `scripts/generate-presentation-metrics.mjs` (pinned by `tests/presentation/presentationMetrics.test.ts`).
- A person is `components/PersonAvatar` (picture by `[user id, sha]`, `rememberFor(Infinity)`, else initials) — never on an agent's note.

## Decided — do not ask again

- Demoting the only project admin is confirmed, never refused (a global admin can add one back); add-member defaults to Viewer. Scope export is the declared scope (`OutOfScopeExport` removed). A failed upload is never a queue row. `PagedFooter`'s look stays.
- A failed NEW-filter read shows only error + Retry; a failed REFRESH keeps the rows and says so. Hosts: a failed Follow neither stales the list nor pauses bulk. Operations: a failed count re-read is "—".
- ForceChangePassword keeps its fields until sign-out finishes; Profile's refusal clears on close. Tool activity: each question replaces the history entry. In the address: Segments' lens, SBOM's filters / page size; Oversight's sort returns to page 1.
- The hand-kept read lists stay (a tag is hand-added too and hides what a write refreshes); NO typed key registry, NO per-type retention beyond `gcTime: 0` without measurements, NO domain-owned invalidation layer.
- Not now: a one-shot migrate service; shared test factories, one logging setup, an ingestion job-context module (wait for a feature). An unattended polling tab signs out; no session upper limit in use, for now. The product's agent contract never moves to the root `AGENTS.md` (which is the repo rules for contributors).
