# Inventory reads: Hosts, the DSL, Scans, Posture, Evidence, Coverage, Operations

Inventory routers mount under `/api/v1/projects/{project_id}` (`project_router` in `api.py`); routes and fields: `documentation/API_GUIDE.md`. Count-opens-its-list, child predicates as EXISTS and DSL `NOT` through `negate` are `AGENTS.md` invariants; this file names each list's one definition.

## One definition each

A new count needs its list (and DSL query) first; every reader calls the one function, never a second copy.

- *Untouched* — `host_query_predicates.untouched_conditions` (no HostFollow, note, non-dismissed host test, evidence record or finding endpoint; five `NOT EXISTS`): the queue, `has:untouched`, the terrain (`test_read_path_review.py`).
- *Planned* / *tested* — `host_test_queries`: planned = a test `proposed` / `in_progress`; tested = evidence with outcome `finding` / `no_finding` / `inconclusive` (a `failed` attempt or an `info` record is not a test). Hosts chips, `has:planned` / `has:tested`, `/coverage`, the terrain, Evidence, the host assessment (`test_has_planned_dsl.py`).
- *Vulnerability-assessed* — `evidence_service.vuln_scanned_filter` (a Nessus/OpenVAS run that found nothing counts); `host_assessment_service`'s eligible / assessed flags are `domain_eligible_condition` / `domain_assessed_condition` for the one host (`test_review_2026_10_23b_inventory.py`).
- *Evidence gap, per host* — `evidence_service.evidence_gap_condition(domain)`: `gap:<domain>`, a row's `evidence_gaps` (`host_evidence_gaps`, one statement per page), the Scope table's `not_vuln_assessed_count`. The Evidence page answers from the id sets (`eligible_host_ids` / `assessed_host_ids`); `test_evidence_gap_predicates.py` pins predicate == set per domain, so both change in one commit. A matrix CELL has no exact query, so no Hosts link.
- Evidence's `web_tls` / `auth_smb_ad` apply only through an OPEN port (`evidence_service._exposing_port_conditions`, shared by the id sets, the predicate and the gap list's ports; `test_review_2026_10_23b_inventory.py`).
- *Segments* — `subnet_insight_service.group_hosts_into_segments` (sites; most-specific subnets when no site): the Posture grid and the Evidence matrix (`test_finding_endpoint_segments.py`).
- *Coverage states* — `scope_coverage.coverage_state_condition` / `coverage_state_count` (= DSL `scope:subnet|name|none`): the Scope page, `/coverage` (its three counts sum to `total_hosts`), `/hosts?out_of_scope_only`, the out-of-scope list, Query `hosts.scope` (`scope_coverage_expression`) (`test_scope_coverage_one_rule.py`). A host reached through an in-scope name is neither subnet-scoped nor out of scope.
- *Imports that need someone* — `operations_read_service.blocked_import_condition` (failed or partial, not dismissed, not superseded): Operations, `/scans/history?status=needs_attention` (its `status_counts`, the queue strip's line), Evidence's `data_quality.imports_needing_attention`, the agents' ingestion issues. The Ingestion Results list, views and counts and `/scans/summary`'s `imports_*` are `ingestion_results_service` (`job_counts`), so each reason the lead names is the list its link opens; an undismissed expiry is both "needs attention" and "expired" (`test_import_attention.py`, `test_one_import_history.py`). `parse_errors_unresolved` counts parse-error ROWS, for agents only; never print it as work.
- *Cross-project counts* — `engagement_metrics_service` (targets, tested, findings, judged / not-yet-judged observations, defect rate, contributors) and `project_signals_service` (workflow signals); Portfolio and Oversight never compute these (hazard — removable: a test that those routers read them only through the two services). "Judged" = `_vuln_coverage` as SQL over stored `vulnerabilities.issue_key` (`test_engagement_metrics.py`); changing `vuln_identity` needs a migration recomputing `issue_key` and `findings.dedup_key`. Cross-project "tested" = in review or reviewed (`engagement_metrics_service.in_review_condition`, correlated EXISTS); the wire name `hosts_tested` stays until Portfolio / Oversight change with it.
- *Active finding* — `engagement_metrics_service.finding_is_active` (open / confirmed AND not a false positive by status or on every endpoint): Posture's active, unowned and `scanner_active` counts, the Findings list's `status=active` on both doors (`test_review_2026_10_23_inventory.py`). Per HOST (the Hosts badge, the inventory downloads): `host_detail_service.active_finding_counts` (`test_finding_active_on_host.py`).
- *A host's conflicts* — `host_detail_service.host_conflict_counts` over `conflicts_per_host`: the host's rows AND its ports'. The Hosts badge, the conflicts pane (`GET /hosts/{id}/conflicts`, those rows under one cap), `assessment.conflicts`, the agent host detail and the queue's tier 5 (`test_review_2026_10_23b_inventory.py`).
- *A stated host state* — `host_query_predicates.state_stated_condition` (not NULL, not `unknown`): the change detector, scan compare's state changes, `up_hosts` (same test).
- *A risky service* — `ports_of_interest.port_of_interest` (+ `port_of_interest_condition`): the exposure chips, subnet insight, Operations tier 4 (`test_review_2026_10_23b_risky_services.py`).
- *Address order* — frontend `utils/ipAddress.compareAddresses` (`ipAddress.test.ts`); server `scope_targets_service.ip_order_by(db)` (as `inet`, an unparseable address last, then id): the exports, scope coverage, remediation, `evidence_gap_hosts`, the scan page's Hosts and Ports tabs. `host_query`'s `ip_sort_key`, `scan_diff_service._address_order` and `query_datasets` write a bare `cast(ip_address AS inet)` because they need a direction or a comparison (hazard — removable: an `address_key(db)` in `scope_targets_service` that `ip_order_by` and those three build on).

## Query rules at scale

- Child-table predicates are written `P.host_has_port(*P.port_match_conditions(...))`, `P.test_label_predicate`, `P._host_has(child.host_id, …)`. `test_read_path_review.py::test_no_host_predicate_is_an_in_subquery_any_more` refuses `IN (subquery)` / `NOT IN` in `host_query_predicates.py` and `host_condition_sets.py`; `test_no_service_filters_hosts_by_an_in_subquery` refuses `Host.id IN (subquery)` in `app/services` bar `delete_partial_scan`'s scan-confined DELETE.
- `id IN (subquery) OR id = <value>` scans the table: put the id INTO the set (`select(...).union(select(literal(x)))`) so rows are found by primary key.
- Issue lookups go through `scanner_observation_service._key_in` / `_key_is`, never `coalesce(issue_key, …) =` (it defeats `ix_vulnerabilities_issue_key`; `test_read_path_review.py`).
- `P.product_version_text()` and the migration's `_PRODUCT_VERSION_EXPR` stay textually identical, or the trigram expression index is unused (`test_read_path_review.py`).
- **A partial index is used only when the filter provably implies its predicate.** `ix_vulnerabilities_signal` (`severity = 'CRITICAL' OR severity = 'HIGH' OR exploitable IS TRUE`) serves the queue's two scanner reads; rewording either side brings full scans back silently. `test_investigation_queue.py::test_the_queues_scanner_row_reads_can_use_the_signal_index` plans the real statement and must name the index twice (it drops `uq_vulnerability_identity`, also `host_id`-first, inside its transaction, so the planner cannot prefer it on a tiny table).
- Select columns, not the `Host` entity, in aggregations.
- **Rank in SQL**: the queue's tier is a `CASE`, Postgres orders and cuts to the limit, `count(*) OVER ()` is the exact total; never bring every signal host to Python. A set used in a column and the `CASE` is LEFT JOINed once.
- Several subnets: `SubnetCorrelationService.correlate_subnets(ids)`, never a loop of `correlate_subnet` (`test_read_path_review.py`).
- **Latest observation wins, in SQL**: `has:cert_issue` / `has:weak_tls` / `has:weak_auth` are `host_condition_sets.*_condition` — EXISTS of a row where the weakness holds with no LATER row of the same thing (a host's URL; protocol + port); later = newer timestamp, a missing one the oldest, a tie → the higher id. Systemic and Subnet Insights use the same (`*_host_ids`, `subnet_insight_service.hosts_by_subnet`); never loop web / login rows in Python or hand the filter an id list (`test_review_2026_10_16_t5.py`). `eol` runs its regex catalog over the DISTINCT OS names in Python and answers `os_name IN (…)`; when it LABELS rows it takes `only_host_ids` (`host_weakness_flags` → `BuildCtx.only_host_ids`).
- **Measure with `jit=off`** (compose: `jit=${PG_JIT:-off}`; a throwaway probe database has JIT on). Signals: the access line ends `db_ms= db_n= route=`, `Server-Timing` carries `db;dur=`, Postgres logs statements over 500 ms and preloads `pg_stat_statements`.
- Address sort adds no count tiebreakers (an address is unique in a project). `hosts.ndjson` pages by key, never OFFSET; the names export reads the list's query ONCE (`yield_per`, a server-side cursor, `_EXPORT_CHUNK` a batch). A capped host list takes the first N of the WHOLE list by address in SQL (IPv6 included), never the first N by id sorted afterwards.
- **"Currently resolves to" is ONE probe per record**: `dns_name_service.current_binding_condition`, EXISTS over the name's newest A/AAAA row (`ORDER BY coalesce(observed_at, created_at) DESC, id DESC LIMIT 1`), served by `ix_dns_records_name_latest_binding` (revision `c8e2a4f6b1d9`). Index order and predicate are the probe's: change both together (`test_review_2026_10_22_read_paths.py::test_the_probe_can_use_the_latest_binding_index`).
- `/hosts/filters/data` caches ONLY the unfiltered scan-derived facets (`HOST_FACET_CACHE_SECONDS`, 30 s per worker); anything a person edits (tags, labels, subnets, sites) stays outside `_scan_derived_facets`. Filtered facets evaluate the filter once and pass the ids as one array parameter (`test_read_path_review.py`).
- Known slow, not yet changed: the Hosts default sort (three correlated counts per host), the unfiltered facets uncached, the queue's change detector (sorts every host-scan-history row).
- Measured and left alone: the facets' three port statements — one `GROUPING SETS` or CTE statement is not faster (grouping dominates); revisit with a stored per-port rollup or a (port, host)-ordered index (`test_read_cost_2026_10_10.py` pins the values).
- Measured and left alone: `finding_service.endpoint_segments` on every endpoint write (`segment.order` is project-wide, so every mapped host is resolved) — revisit when the finding page is felt slow, by grouping hosts by their subnet SET in SQL and running the same rule per set.
- Measured and left alone: report summary reads (a draft recomputes `printed_parts`; an issued one reads the `json` snapshot) — revisit with a checklist read apart or a summary column written at issue; a draft's endpoints are read as columns, not ORM objects.
- Measured and left alone: per-row sighting INSERTs outside Nessus / masscan — batching gained less than run-to-run spread.

## Hosts

- **One filter, two doors.** `host_query.build_filtered_host_query` is the Hosts page's filter AND the agents' assist host reads (`test_assist_ui_parity.py`). `search` = the search box (address, name, OS family, port number, service name / product / aliases); `has_critical_vulns` + `has_high_vulns` = critical OR high; `ports=` with `services=` must be met by ONE open port; `has_open_ports=false` applies TOGETHER with a port / service / state filter (with no state named the list is empty — never drop one).
- **Every discrete parameter is checked** by `host_query.check_discrete_filters`, which `build_filtered_host_query` calls first (no route calls it itself): an empty list, a value outside a closed set (`state`, `port_states`, `follow_status`, `weaknesses`, `checks`) or a bad format (`ports`, `scan_ids`, `tags`, `subnet_labels`, `subnets`, `asns`; parsed by `host_query.parse_port_list` / `parse_id_list`) is a 422 naming it on `/hosts`, `/hosts/ids`, `/hosts/filters/data`. Understood but matching nothing = an empty list (`test_review_2026_10_10_host_filters.py`, `test_review_1008_inventory.py`).
- No address-prefix fallback: `host_query_common.parse_subnets` raises `InvalidSubnet` (the DSL's `subnet:` → 400). Part of an address is `ip:`.
- **An assignee is resolved only inside `P.project_assignees`** (members, active global admins, current holders — the one list the agents' vocabulary and `assigned:` suggestions use); anyone else is `UnknownAssignee` (422 on `assigned_to`, 400 in `q=`), whether or not the account exists (`test_review_2026_10_10_host_filters.py`).
- The retired `watching` is not a filter value on either door (`P.FOLLOW_FILTER_VALUES`, the one list; `test_review_2026_10_23b_inventory.py`).
- The tool-ready export narrows ports with `host_query.port_filter_conditions`; `search` and `q` choose HOSTS and narrow no port (`port:443` is a fact about the host), and the export dialog says so when a query or search is set with no Ports filter.
- The Hosts row's site is `resolve_host_locations(host_ids=…)` — the Posture rule, which inherits.
- **`Host`'s relationships are plain lazy**: a path reading `ports` / `vulnerabilities` / `notes` / `tag_assignments` names the load (`selectinload(Host.ports)`…); `test_host_loading.py` pins that querying hosts is one statement. The leftover `noload(...)` options are redundant (the list passes `host_scripts=[]` to the serializer).
- **The bulk-select cap is ONE constant, `host_query.BULK_SELECT_CAP`** (5000): `/hosts/ids` (ordered by id), the `/hosts/bulk/*` 413, `GET /hosts/` → `bulk_select_cap`, `/hosts/ids` → `cap`; the page shows the number the answer states and keeps no constant. Never raise or remove it (`test_review_1008_inventory.py`).
- Anything serialising notes loads them with `host_serialization.note_load_options()` — the one list of what `_serialize_note` reads (`promoted_findings` is one-to-many; `test_note_serialization_loads.py`).
- `weaknesses=` / `checks=` are the DSL's `has:` flags (`host_query.WEAKNESS_FLAGS`) and `check:` ids, evaluated by the DSL's own builders, never a second predicate (`test_weakness_filters.py`).
- A row's `matched_weakness_flags` / `matched_check_ids` (`host_query.matched_weakness_terms` over `host_query_dsl.positive_weakness_terms`) and its `exposure` chips (`ports_of_interest.exposure_chips`) are the server's; the page only words them (`test_review_2026_10_23b_host_row_weaknesses.py`, `test_exposure_chips.py`).
- A list row carries its OPEN ports plus the ports the active conditions matched, in any state (`host_query.matched_port_condition`, marked `matched_port_ids`; `match_by_product` on the answer); the inspector reads every port from `GET /hosts/{id}`. The page never re-parses the query: `host_query_dsl.positive_port_conditions` walks the server's parse tree (`test_review_2026_10_23_inventory.py`).
- `critical_exploitable_count` is joined on the same vulnerability row; never pair the critical count with the host-wide exploit count.
- The filter matches a CIDR by containment, so a subnet cell links with `AND NOT subnet:"…"` (`exclude_subnets`); implicit AND does not reach a NOT.
- A new DSL field needs a `value_source` that `host_query_suggest._SOURCES` enumerates, or `enum` / `window` / `free` on purpose (`test_host_query_suggest.py::test_every_value_source_is_enumerable_or_deliberately_not`).
- Under a filter the count reads "N of M hosts" (`GET /hosts` → `project_total`). Filters, sort and page derive from the URL (`frontend.md`); rows-per-page is `localStorage` (`utils/hostsPaging`).

## Query (`/query`)

- **A pipe query language over datasets hosts, ports, observations, `findings`, `endpoints`, `web`, `names`, one statement each.** `query_language` = grammar only (BlueStick's own, no third-party code); `query_datasets` = each dataset ONCE (rows of one project joined to `Host`, `base_id`, typed columns + sort keys); `query_service` = compile + run. Never raw SQL, never a typed expression: a needed column is declared (or promoted — column vs blob).
- **No commercial product's name** for the language in UI text, docs, tool descriptions, comments, test names or quick-nav; say "a pipe query language" / "pipe-style". `frontend/src/tests/queryLanguageName.test.ts` refuses it in the frontend, the backend and the docs (`frontend/public`'s default-credentials reference names products on purpose).
- **Search terms are `host_query_dsl` unchanged and describe the row's HOST** (`ports port:445` = every port of a host with 445 open); row conditions are `| where`. Every search command of one query is about ONE host — nodes ANDed before a several-host dataset's `host_filter` (a correlated EXISTS) wraps them (`findings port:445 | search port:22` = one host with both). A host-less dataset declares `"none"`; search terms there are a 400. A dataset declares its row page ONCE (`link_exprs` + `link`); an observation row opens `/observations?issue=`.
- **Every stats / top row opens exactly its rows**: `drilldowns` = the query before the aggregate + `| where col=<value> …` (`isnull` for null); `=` is exact and case-sensitive, so the drilled total IS the count (`test_query.py`, past the group cap too). A new column type needs its literal round-tripping in `_coerce` / `_quote`. Never make `=` case-insensitive: an empty answer gets `hint` from `_case_hint` (`_condition(fold=True)`) — said, never done.
- **After the aggregate, commands work on the ANSWER**: `where` after `stats` / `top` is HAVING over the answer's named columns (`_plan_grouped`'s `answer` map; a `values()` list is refused); `fields` keeps answer columns by index (`_project`), and drill-downs still use every group column. `top … | where` divides `percent` by a scalar subquery of the rows (`run`), never the window over the kept groups. `where` / `fields` after `head` are refused. Column positions are kept for `fields` / `by` / `top`; `top` takes `limit=` on either side; `sort col desc` is refused with the language's `-col`.
- An address column (`QueryColumn.address`) orders as an address (`cast(… AS inet)`, the literal checked first), never as text.
- **Caps** (`ROW_CAP` 500, `GROUP_CAP` 1000, `VALUES_CAP` 20, grammar limits in `query_language`) are stated against `total` ("the first N of M"); never remove one. A cut `values()` list says `truncated_values` (the page and the CSV mark it).
- **Past its cap a listing is paged by key** (`after` = the last row's sort keys + id, `query_service._after`; never OFFSET), answering `start` / `next_after` on both doors; `after` on a stats answer, with `head`, or unreadable is a 400; a page turn is not recorded in history again.
- **A column a page already answers uses that page's rule**: `hosts.site` = `subnet_insight_service.host_site_expression` (pinned host by host to `resolve_host_locations`), `hosts.scope` = `scope_coverage_expression`, `hosts.open_ports` = the `has:open_ports` conditions counted, `observations.judged` = `observation_judged_on_host`, `findings.hosts` = `finding_service.HOST_COUNT_EXPR` (`test_query_observations_2026_10_22.py`). A `hosts` answer with no `where` carries `hosts_q`, the Hosts query listing exactly its rows.
- No remediation field in any dataset: adding one needs the remediation switch and the auditor floor — a design change, not a column.
- The CSV export is `run(row_cap=EXPORT_ROW_CAP)` + `csv_utils` at the auditor floor — never a second compile; it is not a recorded run.
- **Saved queries** (`saved_queries`, `saved_query_service`): mine + shared; any member, viewers included, saves; only the creator or a project admin changes or deletes (403); another's private one is a 404; a shared one outlives its creator (SET NULL). Saving runs `query_service.check`, the SAME `_plan` `run` builds, with no database, so saving refuses exactly what running refuses; a check `run` makes goes in `_plan`, never in `run` alone (`test_query.py::test_saving_refuses_what_running_refuses`, `test_the_check_reads_no_database`).
- **One query history**: the Hosts page's recent queries and the Query page's history are ONE table (`query_history`, `kind`), written only by `query_history_service` — an upsert on the unique (person, project, kind, `by_agent`, `md5(q)`), then FIFO to `CAPS[kind]` (Hosts 50, Query 200). `run_and_record` records a run on BOTH doors (agents' with `by_agent`), a refused one with its error and position; a recording failure never fails the query. A new page with a history adds a kind and a cap, never a table. No read shows another person's entries (`test_query_history.py`).
- The builder reads text only through `GET /query/parse` (`query_service.builder_shape`, the server's grammar) — no client parser. The builder and the editor's completion WRITE text (`utils/queryBuilder`, `utils/queryCompletion`); the page has one request shape. Search-term completion IS the Hosts page's (`components/hosts/queryCompletion.ts`, `useQueryValueSuggest`, `getHostQuerySchema`), run on that segment; after `stats` / `top` it offers `answerColumns`; a text column's values come from `GET /query/values` (a typing aid, no agent route) (`queryCompletion.test.ts`).
- Agents: `/agent/assist/query`, `/query/schema`, `/saved-queries` call the same services (`test_query.py::test_agents_run_queries_and_read_saved_ones_through_the_same_service`).

## Scans

- **Compare's new / dropped hosts are the Hosts language's `scan:<B> AND NOT scan:<A>`** (and the reverse): `scan_diff_service.host_presence` counts and samples with `host_query_predicates.scan_predicate` + `dsl.negate`, and the page links those exact queries (`ScanDiff.hostsOnlyIn`). Never `first_seen_in_scan` ("new since A" is not "new to the project"), never a bare `scan_ids=` (`test_phase1_visibility.py::test_new_and_dropped_hosts_are_the_lists_their_links_open`).
- **Scan compare (`scan_diff_service.compute_scan_diff`, page + agents) counts in SQL and lists the first `row_cap` by address, then port**: correlated `EXISTS` / `NOT EXISTS`, nothing scan-sized in Python; a new comparison adds a count and an ordered LIMIT sample, never a set built in Python.
- **A scan's `renamed_hosts` and `scan_ids=…&renamed_in_scan=true` are ONE condition**, `host_query_predicates.renamed_in_scan_condition` (`hostname_changed AND NOT host_created`, so a row that inherited `host_created` from a deleted scan reads as added); a batch counts distinct hosts; `renamed_in_scan=true` without `scan_ids` is a 422 (`test_scan_renamed_hosts.py`). The agents' host lists take no `scan_ids`; an agent reads `hostname_changed` on `assist_list_scan_hosts` rows.
- Every `/scans` list takes its filters through `scan_inventory_filters.apply_scan_inventory_filters`; a new filter goes there, never per endpoint (hazard — removable: a test that no `/scans` route builds its own scan filter).
- `GET /scans/history` returns only the ORDER of the import history (batches, single files and — analyst+ — uploads not imported, interleaved and paged over every kind at once in SQL, no cap); the page hydrates rows by id (`GET /scans/?ids=`, `GET /scans/batches?ids=`, `GET /ingestion-results?ids=`) so each summary has one implementation. A status filter (`status` / `job_id` / `error_id`) keeps that order; `status_counts` is `job_counts` under the same filters. Below analyst nothing about uploads is listed or counted (403 for the filters) (`test_one_import_history.py`).
- `PATCH /scans/batches/{id}` names an OPERATOR's batch; an agent's (keyed `(agent_session_id, label)`) is a 409. `GET /scans/batches` starts from the batch table, so a batch with only queued or failed files is listed.
- The scan page's host rows are `scan_snapshot_service.scan_host_snapshots` (shared with `GET /agent/assist/scans/{id}/hosts`); its Ports tab is `scan_port_observations` (`GET /scans/{id}/ports`) — the scan's own `port_scan_history` rows, never the hosts' current ports (`test_scan_host_snapshots.py`).
- **The scan page counts nothing in the browser**: its measures and tab labels are the scan's own `total_hosts`, `up_hosts`, `total_ports`, `open_ports`; each tab lists exactly those rows, paged (`usePagedList`, 50 a page, `?page=`), and only the open tab's list is read; "current inventory" pages `GET /hosts/scan/{id}`, its total `total_hosts`. Tab and view are in the URL (`?tab=ports|dns|command`, `?view=current`), written with `replace`; a new tab or view drops `page`.
- **The Scans list chooses its page before it aggregates**: `_which_scans` picks the page's scan ids from the scan rows alone (filters, order, OFFSET / LIMIT), then only those scans' history is grouped; only the `total_hosts` / `new_hosts` sorts group every filtered scan (`test_review_2026_10_16_t5.py` pins every sort's pages == the whole list's order).
- Deleting a scan is the project ADMIN's; its `deletion-impact` counts each figure with the delete's own condition, lists `hosts_with_work` (`host_work.work_on_hosts`, one statement) and refuses 409 `hosts_with_work` until `confirm_hosts_with_work=true`, and 409 `import_running` while an import runs (`test_scan_delete_by_hand.py`; the rest is `ingestion.md`).

## Posture and Evidence

- **What describes the PROJECT goes on Posture; what describes the reader goes on Operations.**
- **The label follows what was OBSERVED, never assignment**: any active critical/high finding is `action_required`; an unassigned finding is a `tier: "work"` row that never drives the label or its reasons.
- No freshness (`AGENTS.md`); `remediation_flow` is pinned absent (`test_posture.py`). Provenance, not freshness: the inspector's "not revalidated" beside a port is the server's `not_revalidated_port_ids` (`host_assessment_service.not_revalidated_port_ids`, the same function as `open_ports_not_in_latest_scan`; `test_host_assessment_and_evidence_gaps.py`) — a later HOST observation that did not re-observe an OPEN port (an hour's sweep allowed); it never says stale or closed and is no age threshold.
- Unassigned opens `site:none`. The strip has three measures (`test_posture.py::test_posture_has_no_needs_evidence_count`).
- **Whether the vulnerability scan authenticated is shown BESIDE "assessed", never part of it**: `evidence_service.vuln_scan_credentialed_condition(state)` (yes / no / not_stated) — the host detail, `/posture/evidence`'s counts (they sum to the assessed count), `vulnscan:credentialed|uncredentialed|unstated` (`test_vuln_scan_credentialed.py`).

- The page's later sections load for themselves: "Where the team has been" (`GET /operations/terrain`, requested when the section scrolls near; three.js fetched only when the reader opens the map — the only 3D surface) and "Scanner observations and scope" (`components/posture/ExposureSection.tsx`; each half says "could not be counted" on failure).
- **`GET /dashboard/stats` is that section's scanner-observation counts and nothing else**: `vulnerability_stats` from `VulnerabilityService.get_dashboard_statistics`, ONE statement (`GROUPING SETS ((severity), ())`: rows and hosts per severity, and hosts carrying any), also read by `/agent/assist/posture`. A failure fails the request, never a null section (`test_review_2026_10_22_read_paths.py`).
- The terrain is one statement grouped in Python: hosts per /24 (IPv6 /64), the stage a CASE over `tested_predicate`, `planned_predicate`, NOT `untouched_predicate` (exclusive), plus `critical_untouched` (`severity_predicate`) — the DSL's own predicates (`test_read_path_review.py`).

## Operations (`/operations`) — the signed-in person's page only

- **Tabs, one full list at a time**: lead → since last visit → Blocked → tab bar with counts (Findings · Hosts · Tests · Changed since review · Pick up) → the ONE selected list as a table, 10 rows a page (`utils/operationsTabs.OPERATIONS_PAGE_SIZE`) → one line about the caller's own agent sessions.
- **Counts and rows are separate requests.** The light call is `GET /operations?include_investigate=false&include_rows=false` plus `GET /operations/investigate?limit=1` for the queue's total (503 → "—"), in parallel. While Pick up is open its count is its list's `queue_total` (taken before the tier filter and page cut), stored under the count's key (`QueueParts.queueTotalKey`; a failed list read leaves "—") and the count's own request is not made, so the ranking runs once. A tab's rows load only when it is opened (`hooks/usePagedList`).
- **The light call re-reads once a minute** (`pollEvery`); the queue total and a tab's list are NOT polled (the queue's ranking is the costliest read). A failed re-read turns the counts to "—" and keeps the list.
- **`setup`** (`has_hosts`, `has_scopes` — the scope has a subnet entry — only; `operations_service.compute_project_setup`, one statement; `test_operations.py`): both false shows the setup block and hides Refresh; Start agent session stays. The page makes no scope-coverage request; `setup` is kept from the last good answer, so a failed minute never swaps the list for a setup block.
- **The first `GET /operations` by a person starts their "seen" cursor**, stamped by the ROUTE with the answer's own `as_of` only when it says `is_first_visit` (the answer is still the first visit's). After that no GET moves it — a reload or the poll cannot swallow changes; only `POST /operations/seen {as_of}` (Acknowledge, the displayed snapshot) does. The service never stamps, so an agent's read never starts or moves it (`test_operations.py`).
- **Each list route is the SAME `operations_read_service` function that produces its count**: `test_operations_tabs.py` pins count == the list paged through, with fixtures larger than a page (a new tab needs its case); `test_operations_redesign.py` pins each count to the Hosts list it opens.
- **The lead never says one total**: findings needing a decision (`my_work.findings_to_decide`), needing report text (`findings_to_write`; the two partition `findings_needing_me`, a finding with both is a decide), tests assigned, hosts in review, what can be picked up — each a link to its tab + filter. `my_work.total` is still returned for agents; `my_work` totals = the tabs' counts (`my_tasks.group_counts`); the agents' preview ranks tasks PER GROUP (one LIMIT over the merged list hid a group).
- The Tests tab is ONE table of three kinds (`kind=assigned|in_review|triage`, each test under its strongest); its count is `tests_assigned + tests_on_hosts_in_review`; claimable ones are shown BESIDE it ("+ N to claim") and never added to `my_work.total`.
- `compute_my_tasks`' In Review reason is a correlated EXISTS on the test row (selected as a column for the row's reasons), never the caller's set bound as a literal IN; the blockers' two counts are whole-set windows over a LIMITed read (`test_review_2026_10_23b_inventory.py`).
- **Pending retests**: the lead's first line is PROJECT-WIDE — `retests_pending {findings, hosts}` (`operations_service.compute_retests_pending`, every endpoint where `finding_needs.retest_stands`, whoever owns the finding), opening `/findings?host_state=retest&status=all`, whose total it is — then the reader's part. `operations_read_service.marked_for_retest_condition` (`finding_needs.has_retest_standing`, correlated EXISTS) is a `decide`; `need=retest` narrows to it (a SUBSET of decide; `decide` + `write` still partition); `need_counts.retest` / `my_work.findings_to_retest` count it; a row says "N hosts awaiting a retest"; the "Retest pending" chip shows only when non-zero (`test_operations_tabs.py`, `test_retest_workflow.py`). The workflow is `triage-tests-proposals.md` → "Retests".
- **The personal tabs list only what needs the reader**: `my_findings` = findings needing their owner, each with `needs` (under investigation, then `finding_needs.needs_of`'s — see `triage-tests-proposals.md`), never a finding merely because it is owned; `write` = nothing to decide, and report text or an image caption missing.
- **Setting or clearing review status, the bulk route and "Still reviewed" need project ANALYST** on both doors; reading review state is every member's; the controls are hidden below analyst (`test_review_status_role_floor.py`).
- **A review is finished with ONE click and records no conclusion.** The one write is `HostFollowService.apply_review_status` (the single route, `/hosts/bulk/follow` and the agents' route): Reviewed stamps `reviewed_at` and leaves a stored conclusion and note alone; leaving Reviewed clears all three. Nothing writes `host_follows.review_conclusion`; it is only DISPLAYED (`utils/reviewConclusion`, `no_action` included) while the row stays Reviewed — no count, list or query word over it, no "Complete review" dialog or required field. The reviewer's optional `review_summary` is written by `PATCH /hosts/{id}/follow` (analyst+, the caller's own finished review, else 409) and never moves `reviewed_at` (`test_review_one_click.py`).
- **DSL words**: `follow:mine` (the caller has it In Review); `follow:revisit` (a finished review of the CALLER's whose host changed after it — `P.my_review_followup_predicate`, one correlated EXISTS over the caller's own follow row; never `has:changed_since_review` narrowed by "reviewed by me", which matches any teammate's review); `follow:in_review` is any teammate's. `conclusion:` is a 400 "Unknown field 'conclusion'" on both doors (`test_operations_redesign.py::test_the_conclusion_query_word_is_refused_as_an_unknown_field`); a saved view (`host_filter_views.filter_json`) holding it shows that error until edited.
- "Changed since review" compares against `host_follows.reviewed_at`, never `updated_at` (every view bumps it). A finished review is "not done" ONLY when the host gained an open port or a critical / high observation after it (`test_a_stored_needs_evidence_conclusion_lists_nothing`); one row per host, `total` is hosts, counted and paged in SQL.
- `POST /operations/followups/still-reviewed {host_ids ≤200}` re-stamps any of the CALLER's own finished reviews; one UPDATE, all or nothing.
- The queue (`investigate`, "Untouched, with a reason") is ordered by a STATED tier, never a composite score; `tier_counts` and totals are taken BEFORE the tier filter and page cut. No DSL query expresses the whole queue (it would copy the ranking `CASE`), so its footer reads "All N untouched hosts in Hosts, with or without a reason".
- State is in the URL (`?tab=`, `?tier=`, `?kind=`, `?need=`; a tab click is a history entry; nothing in localStorage). With no `?tab=` the first non-empty tab opens, decided once per visit. The page is in the URL (`usePagedList` → `hooks/useUrlPage`), returns to 1 when a filter changes, and a tab link never carries `page`.
- A count not known is "—" / "…", never 0; sections fail as `*_unavailable`, never as an empty queue.
- The footer (`QueueParts.PagedFooter`) links to another page ONLY when that page lists exactly the tab's list. A host opened from a tab carries `operationsTab`; "Back to my work" returns via `operationsBackPath`.
- Statement counts are bounded (`test_operations.py::test_operations_query_count_is_bounded`, the light call's bound in `test_operations_tabs.py`): add grouped queries, never per-row ones.
- Session state in server text is `agent_session_service.session_key_state` (live / resumable / ended), never the stored status; it is on every session row as `key_state`. The page's line is `utils/agentRuns.liveSessionsSummary(rows, {mine: true})` over `myActiveSessionFilters`, which never reads the browser's clock (`test_operations_redesign.py`).
- Agents: `assist_get_operations` is the same service keyed to the session's operator and keeps the previews (`include_rows` defaults true); other callers get the queue embedded, with `investigate_unavailable` on failure. `GET /agent/assist/operations/findings` (MCP `assist_list_my_findings`) calls `operations_read_service.compute_my_findings`; `need` is ONE declaration on both doors (`api/params.FindingNeedParam`; `test_agent_assist_operations.py`). The queue's MCP tool keeps its name, `assist_list_worth_a_look`. Status recipes for agents are `documentation/AGENT_GUIDE.md`'s.

- No number cap on the ports a Hosts list row carries (open + matched only).
- No agree / disagree with an agent's proposal on the test row: the Proposals link is enough.
- Scanner observations: every host of an issue starts ticked; unticking narrows.
- Operations' Refresh asking for agent sessions three times (three different questions) stays.
- A host with a weakness flag but no scanner row has no Scanner observations section (the header's derived flags keep the word "Weakness"); a project with only a domain scope is SET UP (2.538.0, decided 2026-11-09 — it reverses 2026-10-10's "still gets the welcome block": engagements against web targets by name are scoped by domains alone; `compute_project_setup.has_scopes` counts a domain entry).
- A host that needs more evidence stays In review; there is no state for it.
- Any project member, viewers included, may save queries; `=` stays exact.
- PARKED until felt in use: subnet listing apart from the scope, a cross-project remediation apply, host neighbours for Prev / Next (findings have theirs since 2.529.0: `FindingService.queue_neighbours` — the pattern to copy), one collaboration feed endpoint, "next unreviewed" in one server read (today `Hosts.tsx` `turnPageFor` walks page by page).
